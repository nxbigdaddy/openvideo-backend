# 短视频AI系统测试计划与验收标准

## 1. 测试目标
- 验证核心链路“标题->故事->分镜->提示词”的正确性与稳定性。
- 验证多用户隔离、权限、任务重试、审计与成本统计是否可靠。

## 2. 测试分层
### 2.1 单元测试
- DTO校验、状态机流转、模板变量注入、错误码映射。
- ProviderAdapter mock测试（超时/429/5xx/结构异常）。

### 2.2 集成测试
- 模块间集成：project/story/storyboard/prompt/job/billing。
- 数据库事务与索引命中验证。
- Redis队列消费、重试与死信转移验证。

### 2.3 E2E测试
- 用户登录->创建项目->批量生成->查询状态->人工编辑->导出。
- 权限测试：不同角色访问受限资源。
- 租户隔离测试：跨工作区读写拦截。

## 3. 测试矩阵（关键场景）
- 正常流程：
  - 单标题生成成功
  - 批量10标题部分成功部分失败
- 异常流程：
  - Provider超时触发重试
  - 模板变量缺失直接失败
  - 重试耗尽进入死信
- 安全流程：
  - 未授权访问403
  - 密钥接口返回掩码
  - 审计日志完整记录

## 4. 性能与稳定性
- 压测指标建议：
  - API P95 < 300ms（不含异步任务执行）
  - 任务吞吐：>= 20 jobs/min（单机基线）
  - 批量100标题在可接受窗口完成（按模型配额评估）
- 稳定性测试：
  - 连续运行24小时无内存泄漏
  - Redis/MySQL短时抖动可恢复

## 5. 数据一致性检查
- 任务成功必须存在对应result与bill记录。
- 删除故事后版本与分镜按软删策略一致。
- 失败任务不应产生成功态下游数据。

## 6. 验收标准（UAT）
- 功能验收：
  - 四项核心功能均可在UI上完成闭环操作。
- 质量验收：
  - 关键接口自动化测试覆盖率 >= 70%。
  - 队列失败重试机制可用且可观测。
- 安全验收：
  - API密钥不明文展示与存储。
  - 跨租户访问全部被阻断并记录审计。

## 7. 测试环境建议
- 环境A：SQLite + Mock Provider（快速回归）
- 环境B：MySQL + Redis + Sandbox Provider（准生产）

## 8. 发布前检查清单
- 迁移脚本执行通过
- 关键E2E通过
- 告警规则生效
- 备份与恢复演练通过
- 回滚方案已验证
